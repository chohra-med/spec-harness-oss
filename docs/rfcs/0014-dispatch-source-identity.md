# Draft RFC: unambiguous dispatch identity and bootstrap boundary

Status: draft source proposal. Destination: next available numbered RFC under `docs/rfcs/`; 0014 was unoccupied at preparation. Paths in this portable draft are repository-relative or synthetic; the private implementation packet owns machine-specific bindings. Not installed or adopted here. This changes the dispatch contract, so `CONTRIBUTING.md` requires an RFC before implementation.

## Problem

The central dispatch template accepts a source revision placeholder described as HEAD, while its surrounding procedure requires exact dirty source identity. A packet embedding identity/pin text in that value has no specified value grammar. Independent dispatch interpretation can reject either the compact or extended form. The phrase nothing else also needs a precise boundary between the caller payload, mandatory startup instructions and provider transport metadata.

## Decision

`commands/sdd.md` section 6 remains the one normative grammar. Add `source pin` and the optional hash-bound `concerns source` to the fixed fields. Use one literal line per field, exact order, one space after colon, no surrounding prose/fences. role is the bare role enum, pass is bare 1 or 2 for reviewer only; all remaining scalar values are JSON strings. allowed files is an array of JSON path strings. source pin is a JSON object with exactly path, sha256, identity string keys. Reject duplicate/unknown keys at both levels, empty placeholders and decoded newlines in paths. Require 64 lowercase hexadecimal SHA-256 values and a Git object identity consistent with the pin's repository object format rather than assuming all Git repositories use SHA-1.

Synthetic verifier payload shape:

```text
role: sdd-verifier
feature: "/work/evidence/example/"
source revision: "0123456789012345678901234567890123456789"
source pin: {"path":"/work/evidence/example/source-pin.json","sha256":"<64 lowercase hex>","identity":"<64 lowercase hex>"}
goal sha256: "<64 lowercase hex>"
allowed files: ["/work/project/.claude/agents/sdd-verifier.md","/work/project/AGENTS.md","/work/evidence/example/source-pin.json"]
return: "role Output"
```

The example is a shape, not a runnable payload: placeholders fail validation. Feature/path roots may be explicit absolute paths for a deliberate external evidence packet; relative paths resolve against the pinned source root. No prose is allowed in path/revision/return fields. allowed files intersects the named role's read contract and cannot authorize additional reads or suppress mandatory policy. The list binds concrete identity/bootstrap paths plus role-permitted file/directory scopes; it cannot contain narrative text or grant a blanket source-parent scope. Return is exactly role Output, resolved against the canonical role owner. Concerns, when permitted, is the final JSON string for tester and reviewer Pass 2 only. The central no-status default no status given has no concerns-source field. Non-default concerns require an immediately preceding concerns source object with exactly path, sha256 and identity strings. All other roles reject either key before opening provenance. Reviewer pass follows role; absent for other roles.

The source-pin path locates identity data, never a summary or verdict. For the existing captured Git format, require exactly root, head, branch, status, diff_head_sha256, cached_diff_sha256, index_sha256, files, identity; index_sha256 may be null for an absent index. The file registry maps relative safe paths to regular-file hash/mode, symlink target/mode, or explicit absence. Validate no duplicate JSON keys, safe relative paths, correct types, canonical identity hash of the object without identity, current Git HEAD/status/diffs/index and the current tracked/nonignored-untracked set and file states. Preserve symlink identity without following it outside the selected root. A source race invalidates the check. Do not execute any text from a pin. The existing algorithm is a compatibility input, not public content to copy from private records. A future compact format is out of scope.

Non-Git stays supported through an explicit identity object with exactly root, marker equal to non-Git, files, dependencies, identity. dependencies has exactly path (the absolute canonical feature/dependencies.json path) and sha256 (exact byte hash). The manifest has exactly schema (integer 1, not boolean), source_files (nonempty sorted unique safe source-relative path array equal to pin.files keys) and packet_dependencies (safe feature-relative regular-file path to SHA-256 map). Require input.md, spec.md, goal.md, plan.md and tasks.md; goal.md must match the payload goal digest. External feature directories are explicit packet roots, while dependencies outside both selected roots remain unsupported/PENDING. Reject duplicate/unknown/mistyped keys, aliases/links/devices/traversal, missing/extra source declarations and stale file states. The pin and manifest are outside the source registry; neither manifest nor pin/dispatch/output/history/feedback can be a packet dependency. Hash inputs first, manifest second, pin/identity third, payload last, preventing circular bindings. Revalidate all declared states and the pin/manifest after the check. The declared relevant source/rule input set is the scope, file states use the same safe registry and identity hashing. Bound manifest and file reads use the existing 1 MiB receipt and 8 MiB file limits. Missing/unreadable inputs or unsupported scope are exit 2/PENDING; unsafe/malformed or mismatched declarations/hashes are exit 1 refusal. None grants read authority or changes gate blindness. Do not pretend a non-Git manifest discovers all future files; the packet's declared dependencies control invalidation. Unknown pin formats remain PENDING, not best-effort accepted. MICRO remains under its current separate light route and gains no hash burden.

Before dispatch, the orchestrator performs deterministic read-only payload/identity preflight using `bin/sh-dispatch-check.py`, staged in a target as its `.claude/spec-harness/dispatch-check.py`. Stage unchanged bin/sh_safe_io.py alongside it for the explicit isolated sibling import. Direct invocation is python3 -I -B <checker> --dispatch <absolute-payload-path>; 0 means DISPATCH-VALID only, 1 refused malformed/stale/unsafe input, 2 unavailable capability or invalid invocation. No new top-level CLI route is needed. The script reports protocol/identity validity only, never acceptance. If preflight cannot validate the payload or identity, it emits an exact refusal cause and no claim that a model gate ran. Roles keep existing tools; goldfish gains no shell authority.

The gate may read its canonical role, this dispatch contract, mandatory instruction chain and neutral source identity metadata as bootstrap. Required startup instruction reads are legitimate; prior conversation, parent summaries, gate verdicts and reasoning remain disallowed for blind contexts. The caller payload alone must match the grammar. Provider envelope/model/effort identifiers go into the orchestrator's dispatch receipt outside that payload. If prohibited content actually entered a context, it remains contaminated; no metadata exemption cleans it retroactively. A client that cannot supply genuine isolation or dispatch the supported payload records PENDING. A manually bound logical role in a real isolated context can be described precisely as manual dispatch; it is not proof of native agent discovery.

Preserve all existing blind-read restrictions, source-recheck exception, reviewer Pass 2 continuation rule and NEEDS_CONTEXT packet-only response route. Field values cannot redefine them. Malformed payload is DISPATCH-CONTAMINATED; absent/stale source or tools are PENDING with the specific reason. No feature FAIL is fabricated when checks could not begin.

## Concerns provenance and safe temporary fixtures

The optional concerns source anchors an external regular JSON envelope by exact byte hash and canonical identity. Exact envelope keys are schema (integer 1, not boolean), source_identity, goal_sha256, context_id, request_sha256, raw_return, concerns_range, identity. Candidate/goal hashes must match the dispatch. context_id is a nonempty single-line actual implementer context identifier; request_sha256 binds its exact saved request. raw_return has exactly safe relative path and sha256 strings, rooted at the envelope directory. concerns_range has exactly integer start/end byte offsets, not booleans. Envelope identity uses the source pin's canonical JSON hash without identity. All hashes are 64 lowercase hex; reject unknown/duplicate/mistyped fields. Envelope/raw return must be distinct regular no-follow files outside the snapshotted source root, read within the existing 1 MiB receipt bound.

Raw saved handback text is exact strict UTF-8 LF text ending with STATUS: DONE_WITH_CONCERNS (one final LF permitted), with no second recognized STATUS line earlier. The nonempty range selects one contiguous complete concerns block above that final line, on UTF-8 line boundaries. The decoded dispatch concerns encoded as UTF-8 must match that byte slice exactly. No-source non-default concerns, source without concerns, default with source, unsafe/missing/stale evidence, mismatched identities/hashes/status/range or inserted/omitted bytes fail closed. Prohibited roles reject both provenance and concerns fields before reading them. Missing/unreadable evidence is PENDING; malformed/unsafe/mismatched input is refused. Structural correspondence does not authenticate a self-declared context: actual-host trace review must still prove origin and complete concern selection.

Hash order is source/goal, then actual request/handback, then envelope, then dispatch. Provenance outputs never enter the source pin or non-Git packet dependency registry and never contain the resulting dispatch hash. Re-read envelope and raw text at validation end. This preserves the existing implementer final STATUS handback contract and requires no provider SDK or native structured-output capability.

On macOS, trusted fixture setup may canonicalize its system-temp parent before creating/pinning any fixture, recording physical paths such as /private/tmp. Production does not canonicalize untrusted source/evidence paths to authorize them: aliased or linked roots and symlink components remain refused. Include physical-temp valid and alias/symlink-negative controls.

## Declared blind-role read scopes

Source/feature containment is insufficient for allowed files. For goldfish and reviewer Pass 1, the selected feature allows only exact input.md, spec.md, goal.md, plan.md, tasks.md, design.md and research.md; reviewer Pass 1 additionally allows exact gates/source-recheck.md. Both reject the feature root, all other feature files/directories, brief/gate/history/transcript/feedback scopes, and broad ancestors that include them. Neutral exact pin/manifest metadata remains bootstrap only. Exclude source-root specs except selected exact packet files, all .spec-harness, and exact .memory/80-feedback.md; reject each forbidden target and ancestor directory scopes even when the target is absent. Use component-wise canonical lexical comparisons, selected feature before reserved source rules, and conservative scope treatment for missing entries; reject broad scopes rather than invent exclusions. The source-recheck exception never grants its parent, sibling, suffix or child paths, or goldfish access.

Preserve applicable named policy/bootstrap files and safe source/test directories. Mandatory policy cannot be suppressed to obtain blindness, and a real required forbidden-history read leaves the context ineligible/PENDING. Tester/verifier/reviewer Pass 2 retain existing role contracts; Pass 2 can read selected evidence. The checker validates declared scopes, not actual agent tools, arbitrary transcript content or inherited context. Actual trace review and role search/inline-brief restrictions remain independently required. Semantic tests cover explicit forbidden and absent targets, broad parents, in-source/external features, exact exceptions and valid policy/Pass-2 evidence, with a removed-condition red control.

## Compatibility and validation

New source versions use this exact grammar. Historical accepted records remain historical under their recorded protocol/rule identity. New gates do not grandfather ambiguous dirty HEAD-only payloads; fill the new fields and dispatch a clean context. MICRO is unchanged. Semantic parser tests, mutation controls, installed parity and actual-client isolation/read-trace controls are required. Static text-token assertions are supplemental.

This RFC does not reset the separate indexing run's two consumed corrections, accept its source, create an installed receipt in the Harness source, authorize publication or claim native role discovery. Source development follows Job 3. The source protocol can be validated by independent Job 3 development audits; do not require the broken target-dispatch contract to approve its own bootstrap correction.
